# 12단계 제작 2 — 정상·금지 API 실측 표 절차

## 무슨 기능인가?

1~11단계의 **정상 요청**과 **금지 요청**을 한 표에 표시합니다. 각 단계당 2행씩 총 22행은 *회귀 확인 목록*이며, 심판의 별도 **41종 시험**과 다릅니다. 41종 시험은 정의된 원본 사건/결과가 제공되지 않았으므로 **미검증(not_assessed)** 상태로 두고 어떠한 통과 건수도 부여하지 않습니다.

이 절차는 기존 서버 API를 호출하는 **읽기 전용 GET** 요청만 일부 자동 실행합니다. 비밀번호·토큰·쿠키 값·개인 메모 본문은 읽거나 출력·저장하지 않습니다. 기존 메모 변경, 탈환 실행, 계정 권한 회수 또는 DB 복원은 하지 않습니다.

## 실행 절차

1. 최신 웹앱에서 기존 계정으로 로그인하고 승인된 인증장치로 기기 인증을 완료합니다. 기기 승인이 풀리면 재인증합니다.
2. **12단계 · 탈환 작전실** 아래 **1~11단계 정상·금지 요청 실측 표**에서 **안전한 GET 요청 실측** 버튼을 누릅니다.
3. HTTP 응답을 받은 경우에만 '실측·기대 일치' 또는 '실측·불일치'로 표시합니다. 네트워크 오류는 '통신 오류', 안전하지 않은 미실행 사례는 '미실행'입니다.
4. 표에서 **정상 200 확인**과 **익명 거부 401/404 확인**을 모두 확인한 다음 **실측 JSON 내려받기**를 누릅니다. 이 파일을 로컬 증거로 보관하되 토큰이나 메모 본문을 첨부하지 않습니다.
5. 원하는 실제 사례가 더 있다면 별도의 정식 시험·승인된 테스트 계정에서 수행하고, **실제 HTTP 상태/요청 ID/시각**을 동일 표 형식으로 증명해야 합니다. 자동으로 41종 통과 처리하지 마세요.

## 각 열의 의미

- **기대 결과**: 현재 서버의 예상 HTTP 상태. '—'는 자동 실행하지 않는 경우이며 기대 결과를 임의로 꾸미지 않습니다.
- **실제 결과**: 브라우저 'fetch()'가 받은 HTTP 상태만 기록하며 미실행은 '—'입니다. 응답 본문은 읽지 않습니다.
- **요청 ID**: 브라우저가 시험 요청 직전에 생성한 UUID. **서버가 발급하거나 인증한 요청 ID가 아니므로 서버 로그 상관관계 증거로 오인하지 않습니다.**
- **확인 시각**: 브라우저가 HTTP 응답 후 기록한 UTC ISO 8601 시각. 'Date' 응답 헤더가 있는 경우 다운로드 JSON에 별도로 보관합니다. 서버 시간과 같다고 단정하지 않습니다.
- **실측 판정**: 상태가 기대와 같을 때만 'measured_match', 다르면 'measured_mismatch', 통신 실패는 'transport_error', 아예 실행하지 않았으면 'not_executed'입니다.

## 자동 실측이 증명하지 않는 것

- 1~5단계의 일부 요청은 **현행 배포의 회귀 확인**이지 당시 취약했던 1~2단계 기능을 다시 실행한 증거가 아닙니다.
- 4단계 타인 자료 ID 조회, 5단계 원본 Supabase REST 익명 요청, 6~8단계 판정기 실행, 9단계 운영 탐지·회수, 10단계 데이터 복원은 이번 버튼으로 수행하지 않습니다. 각각 원본 사건, 별도 인증된 테스트 정보 또는 DB 변경 승인 등이 필요합니다.
- 11단계 정상 'GET /api/operations' HTTP 200과 익명 동일 경로 401은 **실제 허용·거부 HTTP 응답**을 제공하지만 다른 기기에서의 침공 시나리오 전체를 검증하는 것은 아닙니다.
- 버튼 실행 뒤 결과는 화면 메모리에만 존재하고, 로그인/기기 인증이 종료되면 숨깁니다. 다운로드한 JSON은 사용자가 자신의 PC에 보관합니다. 브라우저 저장소나 Supabase DB에 증거를 쓰지 않습니다.
